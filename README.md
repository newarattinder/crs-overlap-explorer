# Reusable CRS explorer

Open index.html in a desktop browser, or run `python3 preview.py` and open the printed loopback URL. The HTML is self-contained and contains only code, the attributed offline GeoNames catalog, Natural Earth basemap and public venue/event catalog. No personal scan is bundled.

Select one experimental CRS v1 JSON export and choose Explore file for individual Events, City atlas, Library portraits and Method & limits. A second export is optional. Add it to unlock Crossed paths, shared events and Conversation sparks, then choose Compare files. Either input slot can be used alone. Drop one file into either card or two files into the shared drop area. Change pair and Clear files reset the comparison. Reloading clears all files. The tool makes no network requests for processing and stores no data in browser storage.

Supported inputs: up to 128 MiB / 500,000 combined photo-video records per file; full-library, limited-selection and explicit sample provenance. Old photo-only exports and additive video exports both work. Geography and crossing comparisons use photos; video metadata counts appear in Library portraits. Unknown smart-album extensions do not change the comparison.

Validation: 27 focused importer/comparison checks in verify.js; browser file-picker checks for distinct pairs, limited selection, original record IDs, future capture years, empty/GPS-free inputs, malformed JSON, duplicate-file selection, literal user-name rendering, change-pair/clear/reload, and mobile input reflow. No browser errors were observed. Drag-and-drop uses the same selection path; it was inspected but not exercised through automation. Real full-library browser throughput remains dependent on library size and hardware. Cancel stops the preparation worker; applying new comparison filters replaces the comparison worker.

Rebuild the self-contained HTML with `python3 build.py` after source edits. This build uses Source's public, attributed offline city catalog. Run `node verify.js` for synthetic fixtures and focused checks. The fixtures contain no user data.

Refined crossing controls: enter inclusive min/max distance in meters or kilometers and min/max timestamp gap in seconds, minutes, hours, or days. Minimum distance is applied during the nearest-match search, so a too-close candidate does not hide a later valid one. Invalid ranges are rejected. Exact timestamp matches (zero maximum gap) are supported.

Subtler crossings starts at 75 m–1.5 km and 30 minutes–18 hours apart. Possible same-day crossings are highlighted and can be sorted first; this is a browsing heuristic, not proof that the people were apart. Dense-event and matching-copy candidates are not highlighted. Use Omit this gathering for the observed cluster's spatial footprint (covering both people's selected endpoints), with two hours of time padding, or Omit this area for an editable radius on every date. Both photos must be inside the exclusion. Name recurring areas yourself; no workplace is inferred. Every omission is reversible, viewable under Review omitted clusters, and discarded when the comparison is cleared or reloaded.

Place labels include state/province and conservative city context where supported by the offline public GeoNames administrative records. Center City resolves to Philadelphia, Pennsylvania; Twentynine Palms to California. Municipality relationships use administrative identity rather than proximity. Public source attribution and hashes are retained in place-context.json. No reverse-geocoding request sends photo coordinates anywhere.

Additional verification: custom mixed units and invalid ranges in the browser; distinct gathering-versus-recurring-area omissions and restore; specific contextual names in conversation starters; light/dark and narrow/wide layouts. Synthetic tests cover inclusive boundaries, skipping too-close candidates, zero timestamp gaps, dense-event omissions, area endpoint containment, restoration, contextual city names, and conservative highlighting. Real-world “together versus apart” accuracy has not been established.

Conversation starters show the closest capture date for each person beside the time gap. Specific crossing prompts rank first, shared-place chapters next, then country exchanges and general photo prompts. Place prompts are no longer capped at three per kind; duplicate crossing place labels remain consolidated. Exact dates stay out of profile-preview mode.


Photo-year sliders are independent in Crossed paths and Conversation sparks. From/through years are inclusive UTC years; All years restores the full available year span. Sparks recompute place/country evidence and dated-photo format totals for the selected years, including dated photos without GPS. Crossing-based drafts also respect the applied crossing filters.

The Events tab provides both individual timelines, shared event listings, category/artist/venue search, year filters, conservative evidence tiers, a local footprint/GPS diagram, source dates, reversible review decisions, manual memories, catalog replacement and public-catalog/evidence downloads. Reviewer confirmation is distinct from a metadata candidate. Both confirmations are required before an event becomes a conversation draft. Photo evidence never leaves the browser. Provider collection runs separately and accepts only public venue identities.

The 2026-10-15 catalog contains 65,684 event records and 278 current venue footprints for US/Europe, with records from 2010 onward. Sources: OSM (ODbL), MusicBrainz core (CC0), nflverse (CC BY 4.0), Retrosheet (required reuse notice), SportsDataverse NBA/WNBA (CC BY 4.0), NHL (MIT), F1DB (CC BY 4.0), OpenFootball EURO 2024 (CC0), Coachella weekend date facts (Wikipedia CC BY-SA 4.0 plus official archive), and an official O2 comedy-date listing. Source attribution and licenses travel with the downloadable public catalog.

Coverage is incomplete: missing venue polygons, renamed/closed venues, unlisted shows, domestic soccer histories, stand-up/theatre, conventions and many festivals remain gaps. Qualified venues without an event record appear in photo coverage. A current outline is not a verified historical footprint. GPS cannot resolve another level/use of a building (e.g. MSG/Penn Station or TD Garden/North Station); these stay under review. No centroid-radius substitutes are used. Festival grounds never identify the artist or stage. Date-only, unknown completion, competing event records, GPS edge uncertainty, and estimated ends cannot pass the strict strong tier. Political and other sensitive event attendance is excluded from automatic matching; explicit manual memories remain separate.

Event verification: 16 focused geometry, confidence, ambiguity, sensitive-event and high-volume checks (`node verify-events.js`), plus a catalog/importer/export round trip preserving original photo/video IDs, source URLs, scan digests, settings and reviewer states. Browser checks use labeled synthetic files. Public-source refresh tooling is in `events/`; raw provider caches, build dependencies, and synthetic photo fixtures are never published. Public map services have bounded retries and collection limits; use licensed extracts or an appropriate hosted service for larger recurring coverage expansion.


BTS MetLife correction: the two August 1–2, 2026 shows were absent from the original music catalog even though the stadium polygon existed. The official MetLife listing and NJ TRANSIT schedule now supply separate dated records, 8 PM scheduled starts and 5:30 PM doors. Admission photos use the published arrival window and remain review evidence; the listing’s scheduled status and estimated finishes are preserved. The catalog summary now distinguishes concert count from total events, which are mostly sports. This fixes these missing records, not comprehensive concert-history coverage. Synthetic regression checks verify arrival captures, separate nights and no false shared-event match.


Coverage audit correction: bind Retrosheet park NYC21 to the current Yankee Stadium polygon (opened in 2009), adding 1,290 Retrosheet games from 2010–2025, including 44 postseason games. This is a stable venue identity binding, not a fuzzy name guess; the retired stadium is not reused. Retrosheet’s snapshot does not include 2026. Events now accept dated GPS video metadata as well as photos, retain separate video IDs and media kinds in evidence/exports, and leave photo crossing and city summaries unchanged. Older photo-only exports explicitly report that video metadata is unavailable. Coverage shows missing GPS, missing dates, outside-year records, exclusion flags, eligible photo/video counts, and records outside known footprints; venue tables show the catalog’s year span. Category selectors show actual catalog record counts. Stand-up remains just three listings, and the Coachella property outline is not a verified full historical festival boundary. The collector now includes both regular-season and postseason archives, preserving each game’s phase and full team names. Metadata without GPS cannot establish festival attendance. The browser accepts video metadata when present; it cannot recover videos omitted by an export.

Single-file verification: 27 importer/comparison checks, 16 event checks, and three single-file worker/export checks. Individual photo-only and video-only event evidence retain one supplied person and original media references. The matching engine uses an empty second-side index internally, never a fabricated supplied person. Browser verification covers one file, a sole file in the second slot, video-only evidence, individual places/detail, charts/methods, empty inputs, and adding a second export. Shared-only tabs and controls are unavailable until two files are supplied. Files remain in memory and clearing or reloading discards the session.

Cloud-file reading: file bytes are read with FileReader progress events, an elapsed-time heartbeat, and a 90-second deadline without new bytes. Cloud-only handles show a local-download hint instead of silently staying on Reading file. Timeout/read errors restore selection and retry controls; cancel terminates the worker. Parsing, validation and fingerprinting have separate status messages. A two-minute unresponsive-worker watchdog covers missing responses. Six focused read/watchdog regressions cover completion, byte progress, stalled reads, progress-reset deadlines, read/abort/open errors and retry recovery. Personal exports remain local and are never bundled or sent to providers. API reference: [FileReader](https://developer.mozilla.org/en-US/docs/Web/API/FileReader).
