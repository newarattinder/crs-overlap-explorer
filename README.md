# Reusable CRS explorer

Open index.html in a desktop browser, or run `python3 preview.py` and open the printed loopback URL. The HTML is self-contained and contains only code, the attributed offline GeoNames catalog, Natural Earth basemap and public venue/event catalog. No personal scan is bundled.

Select one experimental CRS v1 JSON export per person, optionally rename the people, then choose Compare files. Drop one file into either card or two files into the shared drop area. Change pair and Clear files reset the comparison. Reloading clears all files. The tool makes no network requests for processing and stores no data in browser storage.

Supported inputs: up to 128 MiB / 500,000 combined photo-video records per file; full-library, limited-selection and explicit sample provenance. Old photo-only exports and additive video exports both work. Geography and crossing comparisons use photos; video metadata counts appear in Library portraits. Unknown smart-album extensions do not change the comparison.

Validation: 24 focused importer/comparison checks in verify.js; browser file-picker checks for distinct pairs, limited selection, original record IDs, future capture years, empty/GPS-free inputs, malformed JSON, duplicate-file selection, literal user-name rendering, change-pair/clear/reload, and mobile input reflow. No browser errors were observed. Drag-and-drop uses the same selection path; it was inspected but not exercised through automation. Real full-library browser throughput remains dependent on library size and hardware. Cancel stops the preparation worker; applying new comparison filters replaces the comparison worker.

Rebuild the self-contained HTML with `python3 build.py` after source edits. This build uses Source's public, attributed offline city catalog. Run `node verify.js` for synthetic fixtures and focused checks. The fixtures contain no user data.

Refined crossing controls: enter inclusive min/max distance in meters or kilometers and min/max timestamp gap in seconds, minutes, hours, or days. Minimum distance is applied during the nearest-match search, so a too-close candidate does not hide a later valid one. Invalid ranges are rejected. Exact timestamp matches (zero maximum gap) are supported.

Subtler crossings starts at 75 m–1.5 km and 30 minutes–18 hours apart. Possible same-day crossings are highlighted and can be sorted first; this is a browsing heuristic, not proof that the people were apart. Dense-event and matching-copy candidates are not highlighted. Use Omit this gathering for the observed cluster's spatial footprint (covering both people's selected endpoints), with two hours of time padding, or Omit this area for an editable radius on every date. Both photos must be inside the exclusion. Name recurring areas yourself; no workplace is inferred. Every omission is reversible, viewable under Review omitted clusters, and discarded when the comparison is cleared or reloaded.

Place labels include state/province and conservative city context where supported by the offline public GeoNames administrative records. Center City resolves to Philadelphia, Pennsylvania; Twentynine Palms to California. Municipality relationships use administrative identity rather than proximity. Public source attribution and hashes are retained in place-context.json. No reverse-geocoding request sends photo coordinates anywhere.

Additional verification: custom mixed units and invalid ranges in the browser; distinct gathering-versus-recurring-area omissions and restore; specific contextual names in conversation starters; light/dark and narrow/wide layouts. Synthetic tests cover inclusive boundaries, skipping too-close candidates, zero timestamp gaps, dense-event omissions, area endpoint containment, restoration, contextual city names, and conservative highlighting. Real-world “together versus apart” accuracy has not been established.

Conversation starters show the closest capture date for each person beside the time gap. Specific crossing prompts rank first, shared-place chapters next, then country exchanges and general photo prompts. Place prompts are no longer capped at three per kind; duplicate crossing place labels remain consolidated. Exact dates stay out of profile-preview mode.


Photo-year sliders are independent in Crossed paths and Conversation sparks. From/through years are inclusive UTC years; All years restores the full available year span. Sparks recompute place/country evidence and dated-photo format totals for the selected years, including dated photos without GPS. Crossing-based drafts also respect the applied crossing filters.

The Events tab provides both individual timelines, shared event listings, category/artist/venue search, year filters, conservative evidence tiers, a local footprint/GPS diagram, source dates, reversible review decisions, manual memories, catalog replacement and public-catalog/evidence downloads. Reviewer confirmation is distinct from a metadata candidate. Both confirmations are required before an event becomes a conversation draft. Photo evidence never leaves the browser. Provider collection runs separately and accepts only public venue identities.

The 2026-10-15 catalog contains 64,033 event records and 277 current venue footprints for US/Europe, with records from 2010 onward. Sources: OSM (ODbL), MusicBrainz core (CC0), nflverse (CC BY 4.0), Retrosheet (required reuse notice), SportsDataverse NBA/WNBA (CC BY 4.0), NHL (MIT), F1DB (CC BY 4.0), OpenFootball EURO 2024 (CC0), Coachella weekend date facts (Wikipedia CC BY-SA 4.0 plus official archive), and an official O2 comedy-date listing. Source attribution and licenses travel with the downloadable public catalog.

Coverage is incomplete: missing venue polygons, renamed/closed venues, unlisted shows, domestic soccer histories, stand-up/theatre, conventions and many festivals remain gaps. Qualified venues without an event record appear in photo coverage. A current outline is not a verified historical footprint. GPS cannot resolve another level/use of a building (e.g. MSG/Penn Station or TD Garden/North Station); these stay under review. No centroid-radius substitutes are used. Festival grounds never identify the artist or stage. Date-only, unknown completion, competing event records, GPS edge uncertainty, and estimated ends cannot pass the strict strong tier. Political and other sensitive event attendance is excluded from automatic matching; explicit manual memories remain separate.

Event verification: 15 focused geometry, confidence, ambiguity, sensitive-event and high-volume checks (`node verify-events.js`), plus a catalog/importer/export round trip preserving original photo IDs, source URLs, scan digests, settings and reviewer states. Browser checks use labeled synthetic files. Public-source refresh tooling is in `events/`; raw provider caches, build dependencies, and synthetic photo fixtures are never published. Public map services have bounded retries and collection limits; use licensed extracts or an appropriate hosted service for larger recurring coverage expansion.
